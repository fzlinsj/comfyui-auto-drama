# SSH 密码本机安全记忆设计

## 目标

让 Windows 10 上运行的短剧控制台能够按远端环境记住 SSH 密码，后续扫描、生成部署计划和执行部署时不必重复输入；同时提供明确的清除入口，并保证明文密码不进入数据库、配置文件、浏览器存储、日志、Git 或 API 响应。

## 范围

- 支持密码方式的 SSH 凭据记忆。
- 凭据按环境目标隔离，不在不同主机、端口或用户名之间自动复用。
- 仅在一次 SSH 认证成功后保存或替换密码。
- 密码输入为空时，后端可以使用该目标已保存的凭据。
- 用户可以随时清除指定目标的已保存密码。
- 本次不保存私钥口令，也不实现跨机器或跨 Windows 用户同步。

## 方案选择

采用 Windows Data Protection API（DPAPI）加密密码，并将密文存入当前 Windows 用户的本地应用数据目录。DPAPI 密文绑定当前 Windows 用户，不需要在项目中维护另一把可泄露的加密密钥。

不采用以下方案：

- 浏览器 localStorage：前端脚本可直接读取，不满足凭据安全要求。
- SQLite 或 config.json 明文：容易被备份、日志或 Git 意外带出。
- 自建固定密钥加密：密钥和密文位于同一机器，保护强度低于 DPAPI。

## 架构

新增独立的凭据模块 `console/environment_credentials.py`，只负责四件事：

1. 使用 DPAPI 加密和解密 UTF-8 密码。
2. 以不透明的 `credential_ref` 保存、读取和删除密文。
3. 使用原子替换写入凭据文件，避免进程中断产生半写文件。
4. 对外只返回“存在、缺失、不可用”等状态，不返回密码或密文。

凭据文件默认位于 `%LOCALAPPDATA%\ComfyUIAutoDrama\environment_credentials.json`。代码通过环境变量和路径 API 计算位置，不写死用户目录。文件只包含版本号、凭据引用和 DPAPI 密文；项目目录和 Git 中不保存该文件。

现有 `environment_targets.credential_ref` 继续作为目标与凭据的关联字段，不新增 password、encrypted_password 或 private_key 等数据库列。首次保存时生成随机、不透明的凭据引用；清除时同时删除密文并清空目标的 `credential_ref`。

非 Windows 系统上不提供密码记忆能力，但现有临时密码登录保持可用。接口返回清晰的“不支持安全本机存储”状态，不能静默降级为明文存储。

## 数据流

### 首次保存

1. 用户输入 SSH 密码并勾选“记住 SSH 密码”。
2. 前端仅在当前 HTTPS/本机请求体中发送密码和 `remember_password: true`，不写浏览器存储。
3. 后端先使用该密码完成 SSH 认证。
4. 只有认证成功后，后端才用 DPAPI 加密密码、保存密文，并把凭据引用关联到当前环境目标。
5. API 响应仅返回 `credential_saved: true` 和 `has_saved_password: true`。

### 后续使用

1. 前端发现目标已有保存凭据时，密码框可以留空。
2. 后端根据目标的 `credential_ref` 在服务端读取并解密密码。
3. 密码只在当前 SSH 会话创建期间存在于进程内存中，沿用现有短生命周期 askpass 机制。
4. 日志、异常和 API 序列化继续执行凭据脱敏。

### 更新与清除

- 用户输入新密码并勾选记住，且认证成功后，原凭据被原子替换。
- “清除已保存密码”调用专用删除接口。删除密文成功后再清空数据库引用；重复清除按幂等成功处理。
- 使用已保存密码认证失败时，不自动删除凭据，响应只返回 `saved_credential_invalid: true`，界面提示用户重新输入或主动清除。这样可以区分临时网络、服务器状态与密码确实失效。

## 接口与界面

环境扫描和部署请求增加可选布尔字段 `remember_password`。未提供时默认为 `false`，保持现有调用兼容。

目标信息和凭据状态接口只暴露以下非敏感字段：

- `credential_storage_supported`
- `has_saved_password`
- `credential_saved`
- `saved_credential_invalid`

增加清除接口，按环境目标标识删除保存凭据。接口必须验证目标存在，不接受客户端直接提交文件路径或凭据文件名。

“云端环境部署”界面增加：

- “记住 SSH 密码”复选框，默认不勾选。
- “已保存密码”状态提示；存在保存凭据时说明密码框可以留空。
- “清除已保存密码”按钮；没有保存凭据时禁用。
- 清除成功、保存成功、凭据失效和平台不支持的中文提示。

页面刷新后，前端通过后端状态恢复“是否已保存”的显示，不在 localStorage、sessionStorage 或 DOM 属性中保存密码。

## 错误处理与安全边界

- DPAPI 加密或写盘失败时，SSH 操作本身可以成功，但响应明确提示“连接成功，密码保存失败”。
- 凭据文件损坏、引用缺失或 DPAPI 解密失败时，按无可用密码处理，并提示重新输入；不把底层密文或系统异常详情返回前端。
- 保存文件使用限制性权限；DPAPI 仍是主要保密边界。
- 所有含 password、passphrase、credential、askpass 的日志字段继续经过统一脱敏。
- 自动部署计划和任务快照不得复制密码或解密后的内容。
- 清除操作不影响服务器上的 SSH 密码，只删除本机保存副本。

## 测试策略

- 凭据模块单元测试使用可注入的伪保护器验证保存、读取、替换、删除、损坏文件和原子写入，不依赖真实用户密码。
- Windows 专项测试验证 DPAPI 加密后密文不包含明文，并能由当前用户往返解密。
- 环境管理器测试验证：只在认证成功后保存、空密码回退到保存凭据、新密码成功后替换、保存凭据失败时返回正确状态。
- API 测试验证状态与清除接口、重复清除幂等、响应和日志中不含密码或密文。
- UI 测试验证复选框、状态和清除按钮，并继续断言 localStorage 中没有密码。
- 回归测试覆盖扫描、生成部署计划、下载模型和执行部署的现有临时密码流程。

## 完成标准

- 在 Windows 10 上，对某个环境成功登录并勾选记住后，刷新页面并留空密码仍可扫描和部署。
- 不同主机、端口或用户名不会错误复用密码。
- 清除后再次操作必须要求输入密码。
- 数据库、config.json、浏览器存储、日志、API 响应和 Git 差异中均不存在明文密码。
- 非 Windows 平台不会以不安全方式保存密码。
- 相关测试、完整测试、Python 编译检查和 `git diff --check` 全部通过。
