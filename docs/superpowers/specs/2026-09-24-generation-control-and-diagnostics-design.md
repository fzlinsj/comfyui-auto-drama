# 生成任务控制、服务诊断与 ComfyUI 生图设计

日期：2026-09-24

## 1. 背景

当前系统已经能够通过 ComfyUI 提交 MiniMax H3 视频工作流，也能通过 LLM、Agnes、Boogu 和视觉模型完成剧本、图片与质检环节。但实际使用暴露出以下问题：

- 任务失败后只能看到笼统的 `error`，真实 ComfyUI 节点异常藏在后台日志中。
- 失败任务、链式等待任务和更换服务器后的旧任务可能长期显示转圈。
- 重新生成、取消当前任务和取消整批的操作边界不清晰，容易误提交整批。
- 连接检查只能证明 HTTP 服务在线，不能证明 T2V、I2V、R2V 工作流能够产出视频。
- 外部接口缺少独立、可观察的真实测试入口。
- 现有资产生图依赖 Agnes 或 Boogu，ComfyUI 尚不能作为正式生图供应商。
- 高分辨率工作流可能在 RTX 3090 上 OOM，但提交前没有风险提示。

本设计将系统定位为“半自动模式”：系统负责检查、解释和提供恢复手段；用户决定是否修改参数、重试或切换供应商。系统不得擅自降低画质、自动重试或切换到可能收费的服务。

## 2. 目标

1. 在软件内完成任务取消、失败诊断、参数调整和单段重试，无需查看控制台日志。
2. 所有任务都有明确、可持久化的生命周期，不出现无期限转圈。
3. 提交前检查服务器、工作流、节点、模型、素材和显存风险。
4. 为每个外部服务提供无生成的快速检查和需确认的真实测试。
5. T2V、I2V、R2V 必须分别真实生成成功后才能标记为可用。
6. 将 ComfyUI 接入为正式图片供应商，供角色锚点图、场景图和分镜图使用。
7. 保留现有项目、任务记录和已下载的视频，迁移过程不可丢数据。

## 3. 非目标

- 不自动降低用户选择的分辨率或画质。
- 不自动重试失败任务。
- 不自动从 ComfyUI 切换到 Agnes、Boogu 或其他可能收费的供应商。
- 第一版不提供任意 ComfyUI API 工作流的可视化字段映射器。
- 第一版不通过控制台自动安装远程模型或自定义节点；软件只负责检查并给出明确安装指引。
- 不重写剧本、提示词和资产状态规则。

## 4. 总体架构

### 4.1 服务适配层

新增统一服务边界，避免 HTTP 请求、鉴权、轮询和错误解析继续散落在 `batch_console.py`：

- `ComfyUIClient`：封装 `system_stats`、`object_info`、`queue`、`history`、`prompt`、上传、下载、中断和删除排队任务。
- `LLMAdapter`：统一本地及云端 LLM 的快速检查、真实测试和正式请求。
- `ImageProvider`：统一 Agnes、Boogu、ComfyUI 三种图片供应商。
- `VisionAdapter`：统一视觉接口的快速检查、真实测试和正式质检。

所有适配器返回统一结果：

```text
ok, status, elapsed_ms, summary, details, error_code, raw_error
```

`raw_error` 只能写入受控诊断数据，返回前必须执行密钥脱敏。

### 4.2 生成前检查层

提交视频或 ComfyUI 图片任务前执行预检：

1. 服务地址可连接。
2. 获取 ComfyUI 版本、GPU、总显存、空闲显存和队列。
3. 将待提交 API 工作流中的 `class_type` 与 `object_info` 对比。
4. 将工作流使用的模型文件与对应节点的可选模型列表对比。
5. 检查本地参考图存在且可读取。
6. 检查参数范围和已知显存风险规则。
7. 返回“通过 / 警告 / 阻止”三级结果。

显存规则只负责提示和阻止明显危险的误操作，不修改参数。例如 RTX 3090 上的 MiniMax H3 R2V、12 秒、1.0MP、多参考图应显示高风险警告，由用户确认是否继续。

### 4.3 任务生命周期层

任务记录继续存储在现有 SQLite 中。每个剧本分段是逻辑任务，每次提交或重试是独立尝试：

```text
逻辑分段
  ├─ 尝试 1：失败，原始参数
  ├─ 尝试 2：已取消，修改参数
  └─ 尝试 3：成功，最终采用版本
```

尝试状态为：

```text
preflight_pending
preflight_failed
ready
submitting
queued
running
succeeded
failed
cancel_requested
cancelled
stale
blocked
```

状态只能通过显式转换更新。`stale` 表示 `prompt_id` 不在当前服务器的队列和历史中；`blocked` 表示链式任务因上游未成功而不能提交，两者不得显示为运行中。

每次尝试至少记录：

- 逻辑分段 ID、尝试 ID、父尝试 ID。
- 项目、分段名称和版本号。
- 服务器地址及服务器能力指纹。
- `prompt_id`。
- 模式、提示词、分辨率、时长、步数、参考图和链式来源快照。
- 创建、提交、开始、结束时间。
- 状态、失败码、失败节点、用户可读错误和脱敏后的原始错误。
- 输出文件及是否已经下载。
- 用户本次修改的变量。

服务器能力指纹由规范化服务地址、GPU 设备信息、ComfyUI 版本以及本项目所需节点和模型清单的哈希组成。它用于识别地址指向了能力不同的新服务器，不把同配置服务器的一次普通重启误判为不同服务器。

### 4.4 操作界面层

现有 8 步制作流程保留。第 7 步改为任务控制中心；设置区域新增服务诊断中心。资产页保留现有交互，在供应商选择中增加 ComfyUI。

## 5. 任务控制中心

### 5.1 页面结构

页面顶部显示当前 ComfyUI 地址、GPU、显存、队列和最近检查时间。其下按剧本分段展示任务，每段默认显示最新尝试，展开后显示全部历史版本。

支持筛选：全部、进行中、失败、已取消、已完成、服务器已失效。

### 5.2 状态与操作

| 状态 | 可用操作 |
|---|---|
| 待检查 | 检查配置、修改参数、提交本段 |
| 排队中 | 取消本段 |
| 生成中 | 中断本段 |
| 成功 | 播放、下载、重新生成、选择合成版本 |
| 失败 | 查看原因、原参数重试、修改参数后重试 |
| 已取消 | 原参数重试、修改参数后重试 |
| 服务器已失效 | 使用当前服务器重新提交 |
| 等待上一段 | 选择上一段成功版本、关闭链式生成、等待上游修复 |
| 被上一段阻塞 | 查看阻塞来源并处理，不显示转圈 |

“重新生成”与“重试”均只提交当前分段。成功提交后新尝试立即出现在当前分段下，并自动显示状态；用户不需要再点击顶部的整批提交按钮。

### 5.3 取消语义

- 取消排队任务：调用 ComfyUI 队列删除接口并标记为 `cancelled`。
- 中断运行任务：调用 ComfyUI 中断接口。由于 ComfyUI 中断针对当前执行任务，弹窗需显示将中断的准确任务名。
- 取消当前批次：中断属于该批次的当前运行任务，删除该批次的远程排队任务，将尚未提交的链式等待任务标记为取消。
- 取消不会删除已经下载的视频，也不会删除历史记录。
- 删除记录与取消任务是两个不同操作。

### 5.4 服务器失效判定

每次提交保存服务器能力指纹。轮询时同时查询队列和历史：

- 任务在队列中：保持 `queued` 或 `running`。
- 任务在历史中：按执行结果更新。
- 本地已有有效输出：保持 `succeeded`。
- 在两次查询都成功的前提下，新提交任务连续两次轮询都不在队列和历史中：标记 `stale`；连接失败本身不能触发该转换。
- 服务器能力指纹发生变化且旧 `prompt_id` 不存在：立即标记 `stale`。

失效任务可在当前服务器重新提交，但不得假装仍在排队。

### 5.5 链式失败处理

上游失败时，下游进入 `blocked`。用户可以：

1. 先修复并重试上游。
2. 从上游历史中选择一个成功版本作为链式来源。
3. 关闭本段链式衔接并独立生成。

系统不得悄悄改用更早视频或自动降级为 T2V，除非用户明确选择。

## 6. 服务诊断中心

### 6.1 通用展示

每个服务显示：当前脱敏配置、快速检查结果、最近真实测试、耗时、输出、详细错误和最后测试时间。

统一状态：

```text
未配置 / 快速检查通过 / 需要真实测试 / 可用 / 失败
```

只有真实请求或真实生成成功后才显示“可用”。

### 6.2 快速检查

“快速检查全部”不得生成内容，检查范围如下：

- ComfyUI：连接、版本、GPU、显存、队列。
- T2V、I2V、R2V：节点和模型是否满足各自工作流。
- ComfyUI 生图：标准节点和 SDXL checkpoint 是否存在。
- LLM：地址、鉴权和模型列表；供应商不支持模型列表时显示“需要真实测试”，不能误报失败。
- Agnes/Boogu：地址、协议和可执行的无生成检查；供应商无无费用检查接口时显示“需要真实测试”。
- 视觉接口：地址、鉴权和模型列表。
- 本地依赖：素材目录、输出目录、SQLite 和 FFmpeg。

### 6.3 真实测试

每项必须独立点击并确认。弹窗显示模型、工作流、参数、是否可能收费、是否占用 GPU 和预计时间。失败后不自动重试。

| 服务 | 真实测试 |
|---|---|
| LLM | 固定短提示，要求返回约定 JSON |
| Agnes/Boogu | 生成一张带诊断标识的测试图 |
| 视觉接口 | 识别项目内固定测试图并返回约定字段 |
| ComfyUI 生图 | SDXL 生成一张测试图并下载展示 |
| ComfyUI T2V | MiniMax H3，0.2MP、5 秒、4 步 |
| ComfyUI I2V | 使用项目内固定测试图，0.2MP、5 秒、4 步 |
| ComfyUI R2V | 使用项目内固定参考图，0.2MP、5 秒、4 步 |

T2V 成功不能代替 I2V 或 R2V 成功。视频真实测试完成后必须在页面内播放下载结果，才能标记对应模式可用。

## 7. ComfyUI 生图供应商

### 7.1 供应商选择

`image_gen.provider` 支持 Agnes、Boogu 和 ComfyUI。设置中的默认供应商可被单次生成临时覆盖，但失败后不允许跨供应商自动回退。

ComfyUI 图片任务与视频任务共享客户端、状态轮询、取消和错误解析能力。

### 7.2 默认模型与工作流

默认依赖官方 `sd_xl_base_1.0.safetensors`，约 7GB，模型存放于远程 AutoDL 数据盘映射到的 ComfyUI checkpoint 目录。代码和配置只保存模型文件名，不硬编码远程绝对路径。

内置 API 工作流只使用标准节点：

```text
CheckpointLoaderSimple
  -> CLIPTextEncode（正向/负向）
  -> EmptyLatentImage
  -> KSampler
  -> VAEDecode
  -> SaveImage
```

默认参数：

- checkpoint：`sd_xl_base_1.0.safetensors`
- sampler：`dpmpp_2m`
- scheduler：`karras`
- steps：20
- seed：随机生成并记录，可锁定复用
- 角色图：768x1024
- 场景和分镜图：1344x768 或同等长宽比的 SDXL 尺寸

第一版不提供任意工作流映射器。以后可以增加自定义 API 工作流配置，但不得影响内置 SDXL 基线。

### 7.3 异步生成与落盘

1. 提交前运行 SDXL 预检。
2. 创建本地图片任务并提交 ComfyUI。
3. 页面轮询队列和历史。
4. 成功后通过 ComfyUI `/view` 下载到临时文件。
5. 使用图片解码器验证内容有效，再原子移动到素材目录。
6. 任务成功后更新对应角色、场景或分镜资产引用。
7. 失败时保留任务和完整错误，提供原参数或修改参数重试。

## 8. 错误模型

标准失败码至少包括：

| 失败码 | 含义 |
|---|---|
| F-OOM | GPU 显存不足 |
| F-MODEL-MISSING | 工作流引用的模型不存在 |
| F-NODE-MISSING | 工作流依赖节点不存在 |
| F-WORKFLOW-INVALID | 工作流字段、连接或输入校验失败 |
| F-ASSET-MISSING | 本地参考素材不存在或不可读 |
| F-CONNECTION | 服务无法连接或请求超时 |
| F-AUTH | 外部接口鉴权失败 |
| F-SERVER-STALE | 任务属于旧服务器或已被远端清除 |
| F-CANCELLED | 用户主动取消 |
| F-PROVIDER-RESPONSE | 供应商响应格式异常 |

ComfyUI `execution_error` 中的节点 ID、节点类型、异常类型和异常消息必须进入结构化错误。前端先显示用户可读摘要，展开后显示脱敏详情。

## 9. 安全与费用控制

- API Key 不出现在页面正文、日志、任务快照、错误详情或测试结果中。
- 快速检查不得调用内容生成接口。
- 真实测试必须在动作前确认，并标明可能产生费用或 GPU 占用。
- 不提供“真实测试全部”按钮，避免一次触发多个收费服务。
- 供应商失败不得自动跨服务重试。
- 任务重试必须由用户点击，并显示将使用的完整关键参数。

## 10. 兼容与迁移

- 读取旧任务时映射到新的逻辑分段和尝试结构；原任务 ID、`prompt_id`、输出和状态必须保留。
- 已下载或已有 `output_file` 的旧任务保持成功，不因远程历史被清空而降级。
- 无法归属当前服务器的旧未完成任务迁移为 `stale`。
- 现有 Agnes、Boogu、LLM、视觉配置继续有效。
- 新配置项提供默认值，并同步更新 `config.example.json` 和 `CONFIG.md`。
- 所有代码、规则、界面及工作流改动必须在 `console/CHANGELOG.md` 顶部新增记录。

## 11. 测试策略

### 11.1 单元测试

- 状态转换及非法转换。
- ComfyUI 队列、历史、执行错误和 OOM 解析。
- 节点/模型预检。
- 服务器任务失效判定。
- 取消单段、取消批次和链式阻塞。
- 三种图片供应商不得静默回退。
- API Key 脱敏。
- SDXL 工作流构建和参数覆盖。

### 11.2 接口集成测试

使用本地伪 ComfyUI 服务覆盖：

- 正常提交、排队、运行、成功、下载。
- 工作流验证失败。
- OOM 执行失败。
- 队列删除和运行中断。
- 更换服务器和历史清空。
- T2V、I2V、R2V、SDXL 图片的独立诊断结果。

### 11.3 浏览器测试

- 任务筛选、展开历史、失败详情。
- 单段重试后自动显示新尝试。
- 取消确认及状态更新。
- 诊断快速检查和真实测试确认弹窗。
- 图片及视频测试产物预览。
- 桌面和移动端无重叠、文本不溢出。

### 11.4 真实环境验收

在 RTX 3090 AutoDL 实例上分别完成：

- SDXL 图片真实生成。
- MiniMax H3 T2V、I2V、R2V 最低成本真实测试。
- 人工制造缺模型、缺节点、失效任务和 OOM，确认页面给出正确失败码和操作。
- 取消排队任务、运行任务和整个批次。

## 12. 分阶段交付

本设计是总体设计。实施时每个阶段分别建立实施计划、测试和验收检查点；上一阶段通过后才开始下一阶段，避免把任务系统、诊断中心和生图供应商作为一次不可回退的大改动提交。

### 阶段 1：任务基础设施

统一 ComfyUI 客户端、任务状态机、服务器能力指纹、结构化错误和旧数据迁移。

### 阶段 2：任务控制中心

交付单段/批次取消、失败详情、单段重试、链式阻塞处理、筛选和历史版本。

### 阶段 3：服务诊断中心

交付所有快速检查，以及 LLM、图片、视觉、T2V、I2V、R2V 的独立真实测试。

### 阶段 4：ComfyUI 生图

交付 SDXL 工作流、异步图片任务、供应商选择和现有资产流程接入。

### 阶段 5：真实环境验收

完成 RTX 3090 测试矩阵，修复阻断问题并补齐操作文档。

## 13. 验收标准

1. 页面不存在无期限转圈的任务。
2. 所有失败都能显示原因、失败节点和可执行处理入口。
3. 重试只提交指定分段，不需要再次整批提交。
4. 系统不自动降画质、不自动重试、不自动切换收费供应商。
5. 每个外部服务都能独立快速检查和真实测试。
6. T2V、I2V、R2V 只有实际生成并可播放后才显示可用。
7. ComfyUI 可正式生成角色锚点图、场景图和分镜图。
8. 换服务器、远程历史清空和任务取消后，状态能够在两个轮询周期内收敛。
9. 旧项目、旧任务记录和已生成媒体不丢失。
